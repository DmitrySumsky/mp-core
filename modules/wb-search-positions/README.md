# wb-search-positions — позиции карточек WB в поиске, ежедневно и с историей

Модуль стандарта «Пульт» (`../../ПУЛЬТ.md`). Книга Google Sheets раз в день сама снимает позиции
карточек кабинета в поиске Wildberries по их ключевым запросам и копит историю по дням.
Человек ведёт один лист — «Артикулы».

## Что собирается

| Источник | Что даёт | Ключ |
|---|---|---|
| отчёт WB «Поисковые запросы по вашим товарам» (`search-report/product/search-texts`, нужна подписка Джем) | запросы карточки, частотность за 30 дней, средняя позиция WB за 30 дней и за вчера (с рекламой, все регионы), наши заказы | токен кабинета, категория «Аналитика» |
| публичная выдача `exactmatch` | место карточки в органике (без рекламы), регион — `dest` | не нужен |
| публичная карточка `cards/v4/detail` | название и бренд для листа «Артикулы» | не нужен |

Место «как на сайте» с рекламой из облака недоступно: страница поиска закрыта антиботом.
Роль позиции с рекламой играет «WB позиция вчера».

## Листы книги

| Лист | Кто ведёт | Что внутри |
|---|---|---|
| Артикулы | человек: артикул, «Активен», свои запросы через «;» | книга дописывает название, бренд, число запросов, дату и статус |
| Позиции | книга | последний замер: строка = артикул + запрос, сдвиги к прошлому замеру |
| История · органика | книга | место в органике: строка = артикул + запрос, колонка = день, новый день слева |
| История · WB | книга | средняя позиция по данным WB за каждый вчерашний день |
| Запросы WB | книга | сырой отчёт WB текущего прогона |
| Очередь, Журнал | книга | очередь запросов прогона (статус строки = машина состояний) и журнал прогонов |
| Ключи | человек | B1 подпись кабинета, B2 токен WB, B3 `dest`, B4 GitHub-токен (пусто, пока репозиторий открыт), B5/B6 бот и чат, B7 глубина органики, B8 запросов на артикул, B9 час автопрогона |

## Как идёт прогон

1. **Отчёт WB** — пачками по 50 артикулов, два вызова на пачку (30 дней и вчера), 21 с между
   вызовами: лимит 3 запроса в минуту на кабинет. Длинный 429 (WB сам называет паузу) прогон
   пережидает триггером, а не сном; четыре ожидания подряд — сбой с человеческим текстом.
2. **Очередь** — уникальные запросы прогона; один запрос обслуживает все артикулы, которым нужен.
3. **Органика** — страница за страницей до глубины из «Ключи» B7; хосты и версии метода
   перебираются с памятью, ответ 200 без `products` считается чужим конвертом и перезапрашивается.
   Три неудачи — «нет ответа»: в снимке «нет данных», в истории за день пусто, прошлое не затирается.
4. **Запись** — «Позиции», обе истории, отметки на «Артикулах», журнал, оповещение (если задан бот).

Этап работает 4,5 минуты и ставит триггер-продолжение `continueQueue`. Ежедневный триггер
`posDailyTrigger` живой прогон не дублирует, зависший сегодняшний — подхватывает.

## Разработка

```
python tools/build.py        # сборка central/build/central.js: node --check, резолв функций лоадера, скан утечек
node tests/run.js            # тесты на стабах GAS, сеть только сценарная
python tools/deploy.py --registry <реестр книг вне репозитория>     # сборка + тесты + clasp push лоадера
node tools/run_local.js ...  # тот же центральный код локально с настоящей сетью
python tools/seed_book.py ...# залить результат локального прогона в новую книгу
```

Правятся только `central/src/*.js` и `central/preamble.js`; собранный файл руками не трогают.
Репозиторий открытый: идентификаторы книг, ключи, бренды и боевые артикулы сюда не попадают —
реестр книг лежит вне репозитория, сборка сканирует собранный файл и лоадер на утечки
(список запретных слов — файл из переменной `POS_LEAK_WORDS`).

Отклонения от стандарта и их причины — `module.json`, поле `deviations`.
