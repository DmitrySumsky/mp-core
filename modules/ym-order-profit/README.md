# ym-order-profit — ЧП по заказам Яндекс Маркета

Сколько в итоге принесут **заказы вчерашнего дня** — прогнозом по истории своих же заказов,
а не по списаниям вчерашнего дня (Маркет списывает комиссию и буст при доставке, через дни и
недели после заказа, и списания дня — это деньги прошлых заказов). Рядом — факт по дозревшим
дням и юнитка на данных Маркета.

## Линия заказа

1. Заказ дня (`stats/orders`): штуки, цена продавца = Σ всех `prices[]` (покупатель + доплата
   Маркета + баллы), ставка буста — `items[].bidFee`.
2. Выкуп по артикулу — заказы 14–35 дней назад с известной судьбой.
3. Комиссия — действующий тариф (последние начисления «Размещение товара») или тариф вручную
   с листа настроек.
4. Буст продаж — ставка из заказа × доля ставки, которую Маркет реально списывает (по когорте).
5. Доставка и перевод денег — доля от цены; средняя миля — ₽ на доставленную штуку по свежим
   заказам (8–21 день); эквайринг и невыкупы/возвраты — ₽ на заказ.
6. Себестоимость — лист «себес вручную», иначе юнитка кабинета; на выкупленные штуки.
7. Реклама за показы, хранение, подписка — факт начисления дня, отдельными расходами дня.
   Налог — 25 % от маржи, как в юнитке.

Факт удержаний — отчёт `united-marketplace-services`: `commissions[]` в заказе показывает только
остаток сверх взаимозачёта и для расчёта не годится.

## Книга (Пульт)

В книге — только лоадер (`loader/loader.gs`) в отдельном привязанном проекте. Логика —
`central/src/*.js`, собирается в `central/build/central.js` и тянется книгой при каждом клике.

Меню «💰 ЧП ЯМ»: 1️⃣ посчитать за вчера, 2️⃣ обновить юнитку (цены и остатки), 📖 как работать,
📊 что сейчас происходит, 🔌 проверка связи, 🛠 ручной режим (автопрогон, пересчёт без Маркета,
пересборка истории, сброс зависшего прогона), ⚙️ обновить настройки таблицы, ℹ️ версия.

Листы: «🧾 по заказам», «📈 по дням» (с фактом в X–Z), «🧮 юнитка», «⚙️ коэффициенты»,
«📖 как считается», служебные «⚙️ настройки» и «💲 себес вручную».

```
python tools/build.py                                  # сборка: node --check, резолв функций, скан утечек
node tests/run.js                                      # тесты на стабах
python tools/deploy.py --registry <реестр>             # сборка + тесты + лоадер в проект книги
python tools/seed_book.py --registry <реестр> --cogs-xlsx "<кабинет>=<файл>"   # себес списком из кабинета
node tests/real_data.js <реестр> <день>                # смок на боевом кэше
```

Центральный файл уезжает в книги пушем в ветку, на которую смотрит лоадер (`GH_BRANCH`).

## Локальный расчёт (Python)

`tools/yop_engine.py` — эталон модели на Python, `tools/pull.py` — выгрузка сырья,
`tools/seed_cache.py` — засев кэша на Диске из локального сырья. Тесты — `tests/test_engine.py`.

Реестр — локальный JSON вне репозитория: книга, книга с листом ключей, путь к ключу сервисного
аккаунта, папка данных, id проекта скрипта, кабинеты → лист юнитки и имя файла отчёта услуг.
Отклонения от «Пульта» — в `module.json`.
