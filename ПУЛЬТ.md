# ПУЛЬТ — стандарт автоматизаций в Google-таблицах

Версия стандарта: **v1.0.0 — 31.08.2026**. Кодовое слово: **«Пульт»**
(«сделай по Пульту», «пультовый модуль», «переведи книгу на Пульт»).

**Пульт — это не стек, а способ упаковки логики.** Книга перестаёт быть «таблицей со
скриптом» и становится **пультом управления**: пронумерованные кнопки в порядке работы,
красная кнопка = запись во внешнюю систему, отдельная кнопка «жива ли связь», окно
«что сейчас происходит» и инструкция внутри самой книги. Код при этом в книге не живёт —
в ней лежит только тонкий **лоадер**, а вся логика — один файл в репозитории: правка =
один пуш, и все книги на новой версии со следующего клика.

Эталонные реализации: разгруз Ozon (`19`, лоадер v9 + central v2.52.0), раскладка FBS
(`64`), управление ценами (`69`), ответы на отзывы (`70`).

Стандарт **обязателен для новых** автоматизаций и является целью переписывания старых.
Отклонение допускается только с записью причины в `module.json` модуля.

---

## 1. Две половины: тонкий лоадер и центральный код

| Где | Что лежит | Как обновляется |
|---|---|---|
| Книга (Apps Script проекта таблицы) | лоадер: настройки книги, меню, обёртки вызовов, HTML-диалоги | `clasp push` — редко, только при новом пункте меню |
| Репозиторий | центральный код: вся логика одним файлом | один коммит — все книги сразу |

Правила, каждое из которых оплачено боевым сбоем:

- **Меню живёт в лоадере, не в центральном коде.** `onOpen` — простой триггер, ему
  запрещён `UrlFetchApp`.
- **Резолв функции по имени динамически**: `run_(name, args)` тянет код и достаёт
  функцию по имени. Новая функция центрального кода **не требует** правки лоадера;
  правки требует только новая КНОПКА.
- **Имена точек входа не переименовываются**: на них завязаны пункты меню и уже
  установленные триггеры (в том числе обработчик облачных продолжений).
- **Настройки книги объявляет только лоадер.** Центральный код не объявляет ни одной —
  иначе затрёт настройку конкретной книги.
- **Скоупы OAuth выдаются по статическому анализу**, а загруженный по сети код анализатор
  не видит: в лоадере держится функция-«витрина» `__scopes_()` со всеми сервисами
  (включая операции записи), а в `appsscript.json` — явные `oauthScopes`.
- **Манифест при обновлении логики не трогается**: новый скоуп = переавторизация всеми
  пользователями книги. Изменение манифеста планируется отдельно и объявляется вслух.
- **Ключи (API, токен репозитория, чат оповещений) — на служебном листе книги** или в
  Script Properties. В коде — никогда, в репозитории — никогда.
- **Деплой делает Клод сам, тем же заходом, что и правку.** «Сделал версию, но не
  задеплоил» — недоделанная работа.

## 2. Меню: порядок работы, а не список функций

```
📦 <Название>
  1️⃣ 🔄 Обновить данные из <источник>
  2️⃣ 🧾 <Подготовить/собрать>
  3️⃣ 🔴 <Записать во внешнюю систему>
  4️⃣ 📅 <Финальный шаг>
  ──
  📖 Как работать (инструкция)
  📊 Что сейчас происходит
  🔌 Проверка связи
  ──
  📁 Документы ▸    🛠 Ручной режим ▸    📚 Справочники и диагностика ▸
  ──
  ⚙️ Обновить настройки таблицы
  ℹ️ Версия кода
```

- **Пункты пронумерованы в порядке работы.** Человек идёт сверху вниз; порядок кнопок и
  есть инструкция первого уровня.
- **🔴 — только у пунктов, которые пишут во внешнюю систему.** Читающие пункты метки не
  имеют никогда: метка должна означать одно и то же во всех книгах холдинга.
- **Редкое — в подменю.** Плоский список из двадцати пунктов оператор не читает.
- **🔌 Проверка связи — отдельный пункт и БЕЗ ретраев**: все кабинеты одним `fetchAll`,
  код ответа сам становится диагнозом. Диагностика, умеющая ждать, умирает по
  шестиминутному лимиту и выглядит как «кнопка не работает». Показывает по каждому
  кабинету: есть ли ключ, до какого числа живёт, отвечает ли ручка и **разрешена ли
  запись** (право токена проверяется ДО красной кнопки, а не после).
- **📊 Что сейчас происходит** — одно окно вместо чтения статусов в трёх листах:
  идентификатор текущей работы, этап, счётчики и **ОДНО действие**, которое сейчас нужно
  от человека («впишите сроки и жмите 4️⃣», «идёт работа в облаке — ничего не нужно»).
- **⚙️ Обновить настройки таблицы** — миграция служебных листов без боевых действий:
  после обновления кода человек не должен «прогонять боевой запуск, чтобы появились
  колонки».

## 3. Диалоги: HTML рисует лоадер

`HtmlService.showModalDialog` работает **только из статического кода проекта** (скоуп
`script.container.ui` выдаётся по статическому анализу). Схема:

- центральный код отдаёт `{ html, text }` — готовую разметку и запасной текст;
- лоадер показывает окно, а если не открылось — тот же текст через `ui.alert`.

Диалог обязателен для любой записи во внешнюю систему:

1. **Сначала сухой прогон**: что уйдёт, сколько строк, в какие кабинеты, какие значения
   меняются, сколько из них подозрительных.
2. **Подтверждение с цифрой**, а не «вы уверены?»: «Отправить 47 цен в 4 кабинета? Из них
   3 меняются больше чем на 20 %».
3. **Второе подтверждение** — только для необратимого и массового.
4. **Галочки по строкам**, если запись идёт пачкой: упавший на лимитере кабинет
   повторяется без уже уехавших строк.

## 4. Инструкция внутри кода, привязанная к версии

- Инструкция — **функция центрального кода** (`<модуль>Help`), а не файл на Диске: файл
  читают один раз, и через две версии он врёт.
- Кнопка «📖 Как работать» открывает окно; текст описывает **весь** текущий функционал:
  каждый пункт меню, каждую колонку, которую заполняет человек, каждое ограничение.
- Стиль инструкции — «нажать это, потом это»: пронумерованные шаги, красная плашка на
  единственное правило, которое нельзя нарушать, и раздел «если что-то пошло не так» с
  первым шагом «откройте 📊 Что сейчас происходит».
- **Изменил функциональность — в том же заходе обновил инструкцию и версию.**

## 5. Версии и история

- Semver `vX.Y.Z` в шапке главного файла вместе с датой.
- **Новая версия = новый блок сверху**, старые блоки не переписываются и не удаляются:
  история версий и есть память проекта (`v2.10.1 → ОТКАЧЕНА` — тоже запись).
- В блоке — **причина, а не список правок**: первой строкой заглавными «что болело и
  откуда пришло», дальше пунктами что поменялось, в конце — число тестов.
- Версия видна человеку: пункт «ℹ️ Версия кода» и подпись в окне инструкции.

## 6. Данные и листы

- Колонки ищутся **по заголовку**, а не по букве: люди вставляют свои колонки.
- Колонки, которые заполняет человек, окрашены и перечислены в инструкции; скрипт их не
  переписывает.
- **«Ошибка сбора» в ячейку не пишется никогда** — только «нет данных» / «нет карточки».
  Молчание источника не затирает собранное.
- **Формат ячейки ставится ДО записи значения**: идентификатор в 19 цифр, записанный
  раньше формата «текст», превращается в `1,02E+18` необратимо.
- **Отсутствие данных ≠ запрет.** У справочного значения три состояния: «есть», «точно
  нет», «не знаю»; «не знаю» обязано вести себя как «не мешаю» и говорить о себе вслух.

## 7. Состояния, очереди и безотказность

- **Статус строки = машина состояний**: по статусам очередь восстанавливается после
  любого сбоя. Прерванное в опасный момент получает статус НЕ из pending-набора, иначе
  очередь создаст дубль.
- **Долгие прогоны — в облаке**: этап работает 4,5 минуты и ставит триггер-продолжение
  (лимит исполнения ~6 минут). Никаких `Utilities.sleep` на минуты — это выжигает
  суточную квоту триггеров.
- **Вахтёр**: отдельный триггер раз в N минут проверяет, жива ли очередь, и
  перезапускает; у него есть режим «жив, но делать нечего», иначе он удаляет сам себя.
- **Статус «непонятно, что случилось» обязан быть ВРЕМЕННЫМ**: счётчик попыток хранится
  в строке (переживает перезапуск), человека зовут только после исчерпания.
- **Блокировка повторного нажатия**: `LockService` на время прогона плюс отметка «уже
  отправлено» в строке.
- **Исход опасной операции спрашивают у API**, а не гадают: идентификатор операции
  сохраняется в строку ДО вызова, восстановление идёт тем же кодом, что и боевой путь.
- **«Успех» = проверенный результат**, а не «код не упал»: у этапа есть измеримый
  критерий полноты (сколько строк — столько файлов), несовпадение попадает в статус и в
  оповещение.

## 8. Оповещения

- Форма одна на всю систему: **шапка → тело → действие**. Последняя строка — либо задача
  человеку, либо «ничего делать не нужно».
- Считаются **события по причине**, а не сообщения за заход: дайджест `{причина: {сколько,
  примеры ≤3}}`; при переполнении мелкие группы схлопываются в «прочие причины» СО
  СЧЁТОМ.
- **Сырой ответ API в чат не уходит никогда** — он идёт в колонку ошибки, под подписью
  «для разбора».
- Работу, которую доделывает конкретный человек, помечают его тегом: без упоминания
  сообщение тонет в общей ветке.
- **Число в сообщении считает работу человека, а не итерацию кода**: «18 из 18» про
  внутренний заход очереди — это ложь про отвозку из 120 строк.

## 9. Сквозной номер сущности

Если люди обсуждают сущность вслух («та поставка», «эта отвозка»), у неё обязан быть
короткий номер, и он обязан стоять во ВСЕХ артефактах: строке сводной панели, имени
папки, имени файла, шапке сообщения в чат.

- Счётчик живёт там, где он **один на всех** (сводная книга-панель), а не в каждой книге.
- Номер принадлежит **сущности, а не нажатию кнопки**: повтор и догон его не двигают.
- Перед выдачей номер **спрашивается** у своих же данных: свойства скрипта живут не
  вечно, а работа длится сутками.
- Добавление номера в имя ломает поиск по имени: все сверки переводятся на имя **без**
  номера.

## 10. Документ, который читает человек снаружи

- Любой артефакт, отданный наружу (файл склада, выгрузка, сводка), **приводится к факту**
  после расхождения плана и факта; расхождение называется отдельным листом с причиной.
- Документ называет то, что **физически** происходит (короб/палета — разные колонки, а не
  «мест: 23»).
- **Неполный этап не имеет права переписывать внешний документ**: половина работы — это
  не факт.
- Ошибка, ушедшая только в чат, до исполнителя не доходит: её место — в документе и в
  статусе строки.

## 11. Тесты, сборка, деплой

- Логика гоняется **в Node на стабах** (`SpreadsheetApp` / `UrlFetchApp` / `Utilities`
  подменены). `FakeSheet` проверяет размерность `setValues` — именно на ней падает боевой
  Apps Script.
- Запросы на запись в тестах копятся в массив и сверяются как полезная нагрузка:
  проверяется, ЧТО ушло бы, а не «код не упал».
- **Сборка центрального файла — со встроенными проверками**: `node --check`, резолв всех
  публичных функций, скан на утечки (бренды, идентификаторы, адреса, фамилии). Сборка,
  не прошедшая проверки, **не оставляет файл на диске**, а деплой смотрит на код возврата
  сборки, а не на последние строки вывода.
- Если артефакт собирается из частей, а какая-то часть добавляется ПОСЛЕ сборки — эта
  часть обязана быть внутри сборки, иначе теряется при первом же билде.
- Перед пушем в чужой привязанный скрипт — проверка на двойное объявление точек входа.

## 12. Модуль монорепозитория

Каждая автоматизация — **модуль** одного репозитория, а не отдельный островок.

```
mp-core/
├── libs/                     общее: ядро Python, ядро Apps Script
├── modules/<имя>/            один модуль = одна автоматизация
│   ├── module.json           контракт модуля (см. ниже)
│   ├── loader/               лоадер книги + appsscript.json
│   ├── central/              исходники и собранный центральный файл
│   ├── tests/                Node-стабы / pytest
│   └── README.md
├── registry/books.json       книги, script_id, кабинеты
└── tools/                    сборка, деплой, заведение модуля
```

`module.json` — единственное, что читают общие инструменты:

```json
{
  "name": "wb-fbs-distribution",
  "kind": "gas",
  "central": "central/build/central.js",
  "loader": "loader/loader.gs",
  "books": ["book-key-1", "book-key-2"],
  "tests": "node modules/wb-fbs-distribution/tests/run.js",
  "deviations": []
}
```

- модуль **не импортирует** код другого модуля; общее — только `libs/`;
- новый модуль заводится инструментом, а не копированием чужой папки;
- отклонение от Пульта записывается в `deviations` с причиной — молчаливых исключений нет.

## 13. Чек-лист приёмки нового модуля

- [ ] в книге только лоадер; логика — в репозитории, обновляется одним пушем;
- [ ] пункты меню пронумерованы по порядку работы, 🔴 стоит ровно у записи наружу;
- [ ] есть «🔌 Проверка связи» без ретраев, показывает и право записи;
- [ ] есть «📖 Как работать» из кода и «📊 Что сейчас происходит» с одним действием;
- [ ] запись наружу: сухой прогон → подтверждение с цифрой → журнал → блокировка повтора;
- [ ] версия в шапке + блок истории с причиной; инструкция обновлена тем же заходом;
- [ ] ключи на служебном листе, в репозитории их нет; скан утечек в сборке;
- [ ] тесты на стабах зелёные, сборка и деплой сделаны Клодом в том же заходе;
- [ ] `module.json` заполнен, книги вписаны в реестр.

## 14. Что это даёт

Один человек открывает любую книгу холдинга и работает без сопровождения: меню читается
одинаково, красная кнопка везде значит одно и то же, инструкция описывает ту версию,
которая сейчас в книге. Правка логики доезжает до всех книг одним пушем, а не походом по
кабинетам. Ошибка объясняется словами и называет следующее действие — поэтому оператор
зовёт разработчика реже, а когда зовёт, приносит номер и текст, а не «оно не работает».
